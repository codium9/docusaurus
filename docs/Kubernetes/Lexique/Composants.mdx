#### **Control Plane (Master)**  

_kube-apiserver_ : Point d'entrée REST unique qui valide et transmet toutes les requêtes du cluster  
_etcd_ : Base de données clé-valeur distribuée stockant tout l'état et la configuration du cluster  
_kube-scheduler_ : Assigne chaque nouveau Pod au nœud le plus adapté selon les ressources et contraintes  
_kube-controller-manager_ : Exécute les boucles de contrôle régulant l'état réel vers l'état désiré (nœuds, réplicas, etc.)  
_cloud-controller-manager (optionnel)_ : Fait le lien avec les API d'un fournisseur cloud (Load Balancers, stockage, routes).  

#### **Nœuds d'exécution (Workers)**

_Container Runtime (containerd, CRI-O)_ : Moteur bas niveau qui télécharge les images et exécute les conteneurs.  
_kubelet_ : Agent local s'assurant que les conteneurs décrits dans les spécifications de Pods tournent et restent sains.  
_kube-proxy_ : Gère les règles réseau de l'hôte (iptables/IPVS) pour router le trafic vers les bons Pods via les Services.  

#### **Extensions indispensables (Addons)**

_Plugin CNI (Calico, Cilium, Flannel)_ : Attribue les adresses IP aux Pods et gère le routage réseau entre tous les nœuds.  
_CoreDNS_ : Serveur DNS interne assurant la résolution de noms pour la communication entre Services et Pods.  

#### **Outils d'administration**

_kubeadm_ : Outil CLI pour initialiser le cluster, générer les certificats TLS et joindre les nœuds.  
_kubectl_ : Client CLI permettant à l'administrateur d'interagir avec l'API Server.
